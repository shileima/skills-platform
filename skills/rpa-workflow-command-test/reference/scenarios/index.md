# 测试场景索引

用户指定场景时读取对应场景文件；未指定时可询问，或默认 **baidu**。

> 所有场景均遵循 [test-workflow.md](../test-workflow.md)：**rpa 首页 → 点工作流 → 新建空工作流 → 编排区按序加指令 → 配表单保存 → 调试运行 → 查聊天区日志与红色 icon → 修复**。

## 通用执行顺序（不可打乱）

```
打开网页 → （新建 Tab 批量采集 XPath）→ 输入文本 → 点击元素 → 调试运行
```

**插入约束**：新指令必须**追加在已有指令之后**（非首条指令：选中最后一条已保存指令 → Enter 创建空行 → 右侧搜索框搜索+双击插入），禁止在开始节点后或已有指令之间插入。插入后校验「打开网页」在「输入文本」之前。详见 `insert-command.md`、`ax-verify.md` §插入后顺序校验。

**调试前终检**：全部保存后、点「调试」前，必须对照场景「指令节点」表做整链顺序终检（`test-workflow.md` §调试前场景顺序终检）。终检未通过禁止调试。

## 扩展新场景

1. 在 `reference/scenarios/` 下新建 `<场景名>.md`
2. 更新本文件的「可用场景」表格
3. 在 SKILL.md 的 description 中补充触发关键词（可选）

每个场景文件应包含：
- 目标描述与工作流命名建议
- 指令节点表（引用 `reference/commands/` 下对应文件）
- 元素选择器（实测值或采集要求）
- 逐步执行清单
